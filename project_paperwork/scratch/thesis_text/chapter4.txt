System Design System Architecture The system is an eight-stage pipeline. A query enters at stage 1 and exits at stage 8 carrying an answer, source list, confidence breakdown, and hallucination flags. Each stage is independently optional: if a component fails to initialise --- for example, the DeBERTa NLI model is not loaded because available ram is below threshold --- the pipeline skips that stage rather than aborting. On constrained hardware, disabling the 400 MB NLI model while keeping everything else functional is considerably more practical than hard failure. enumerate Query enhancement: The raw question is passed through a query expander that generates 2--3 alternative phrasings using TinyLlama, broadening the retrieval pool. This stage is skipped if the expander is disabled. Hybrid retrieval: bm25 and dense retrieval run in parallel. bm25 queries the pre-built rank-bm25 index loaded from the pickle cache; dense retrieval queries ChromaDB with the SentenceTransformer embedding of the (possibly expanded) query. The top-$k$ results from each are merged using rrf. Corrective RAG: A lightweight quality check evaluates whether the retrieved documents are relevant to the question. If the top document scores below a threshold, the retriever issues a fallback query with a rephrased version of the question. This step was introduced after observing that questions with ambiguous medical terminology sometimes retrieved tangentially related passages. Grounding gate: The max(abs adaptive llm generation entirely and instead calls _build _extractive _answer(), which selects the single most relevant passage from the retrieved set and returns it verbatim as a conservative, source-backed response. This abstention-and-extract design prevents the model from hallucinating an answer when the knowledge base cannot adequately support one. Context compression: For long-context queries, retrieved documents are summarised to fit within the model's context window. TinyLlama uses a 2048-token limit; BioMistral uses 4096 tokens. LLM generation: The compressed context and question are formatted into a prompt and passed to the active backend. TinyLlama runs via the HuggingFace Transformers pipeline in bfloat16; BioMistral runs via llama-cpp-python. Factual consistency check: The generated answer is compared against each retrieved source using the DeBERTa nli model. A high contradiction score across multiple sources triggers a hallucination flag in the response. Confidence scoring and attribution: Five signals are computed and combined using learned weights, then passed through Platt scaling to produce a calibrated score. Detailed Design Hybrid retriever The HybridRetriever class in src/retrieval/hybrid _retriever.py manages both retrieval backends. At startup it loads the BM25 index from the pickle cache, or rebuilds it from ChromaDB if the cache is stale or missing. Rebuilding takes 30--60 seconds on the 505,584-document corpus, so the cache is essential for acceptable startup time. The rrf fusion formula is: equation RRF(d) = r w_r{k + rank_r(d) equation where $R$ is the set of ranked lists (BM25 and dense), $k = 60$ is the rank constant, $w_r$ is a per-list weight (1.0 for both by default), and $ rank_r(d)$ is the rank position of document $d$ in list $r$. Documents absent from a list are assigned rank $ infty$ and contribute zero to the sum. After fusion, source diversity filtering limits the contribution from any single dataset to prevent the top results being dominated by one corpus. Dynamic $k$ selection adjusts the number of retrieved documents based on query complexity: factual queries use $k=5$; research-type queries use up to $k=10$. figure[!ht] centering images/hybrid_retrieval_final.png Hybrid retrieval component architecture showing BM25 and dense retrieval paths, RRF fusion, source diversity filtering, and dynamic-$k$ selection. fig:detailed_arch figure Multi-signal confidence scorer sec:confidence The MultiSignalConfidenceScorer class in src/xai/multi_signal_confidence.py computes five signals and combines them linearly before applying Platt scaling. Sentence-boundary splitting preserves medical statement integrity --- a bm25 query for a specific term will not retrieve a chunk containing only the tail of a broken sentence. The overlap ensures that sentences at chunk boundaries appear in two consecutive chunks, reducing the chance of a relevant passage being missed entirely. Safety guardrails The SafetyGuardrails class in src/safety/guardrails.py applies two layers of filtering. The first checks for emergency patterns --- chest pain, difficulty breathing, stroke signs, self-harm language, requests for specific prescription quantities --- before retrieval runs. A match returns a redirect message immediately without running the pipeline. The second layer is applied post-generation: an aggressive stop-word list prevents the model from completing exam-style multiple-choice patterns that appear in the MedMCQA training data.

Methodology and Testing Evaluation methodology Test set construction The primary evaluation set contains 97 questions drawn from the three source datasets: 40 from ChatDoctor-HealthCareMagic (clinical symptom and advice questions), 32 from PubMedQA (research-oriented biomedical questions), and 25 from MedMCQA (factual medical knowledge questions). Questions were selected to cover the four query types the system handles: factual definitions, symptom-based questions, research questions, and clinical procedural questions. All 97 questions were held out from knowledge base construction; the source documents are in the knowledge base, but the specific question-answer pairs were not used during any training or fine-tuning step. The dashed red path is the re-retrieval loop triggered when the grounding gate rejects the initial context. fig:eval_pipeline figure Evaluation metrics Results are reported using three complementary metrics, chosen because no single metric captures all relevant aspects of medical answer quality. enumerate Keyword coverage: Fraction of medical terms from the reference answer that appear in the generated answer. Terms are identified by matching against a biomedical terminology list. This metric rewards answers that cover the relevant clinical vocabulary regardless of phrasing --- a model that uses different words to convey the same clinical content will still score well. ROUGE-L: Longest common subsequence F1 between the generated and reference answers~ lin2004rouge. ROUGE-L captures structural similarity but is sensitive to phrasing variation. A model that answers correctly in different words will score lower than one that closely paraphrases the reference. BERTScore F1: Contextual embedding similarity between generated and reference answers~ zhang2019bertscore. More robust to paraphrasing than ROUGE because it measures meaning rather than surface overlap. Scores are reported in rescaled mode (baseline for uninformative responses subtracted). enumerate Confidence intervals throughout are 95 % bootstrap intervals over the 97-question set unless stated otherwise. QLoRA fine-tuning methodology QLoRA~ dettmers2023qlora adapts TinyLlama by inserting low-rank matrices into the attention projection layers. The base model is loaded in 4-bit NF4 quantisation; only the adapter weights are updated during training. This makes fine-tuning feasible on a Colab T4 without running out of gpu memory. Calibration methodology Calibration was measured using Expected Calibration Error ( ece)~ naeini2015obtaining, which quantifies the mean absolute difference between predicted confidence and empirical accuracy across confidence bins: equation ECE = b=1^{B |B_b|{n acc(B_b) - conf(B_b) right| equation where $B_b$ is the set of samples in bin $b$, $n$ is total sample count, and $ acc(B_b)$ and $ conf(B_b)$ are mean accuracy and mean confidence within that bin. Ten equal-width bins were used. The binary label for calibration was keyword coverage thresholded at 0.3: a response is counted as correct if at least 30 % of reference keywords appear in the generated answer. Platt scaling fits a logistic function $ ece is not reported as a separate metric; a proper estimate would require a disjoint hold-out set. Testing Unit tests The test suite contains 250 passing tests, run with pytest tests/ -k "not langsmith". Coverage includes: itemize RecursiveSentenceChunker: 10 tests covering chunk size bounds, overlap, sentence boundary preservation, and edge cases (empty input, single sentence, very short text). MultiSignalConfidenceScorer: one test per signal using synthetic inputs with known expected outputs. SafetyGuardrails: pattern matching for emergency, prescription, and self-harm trigger categories. CacheManager: TTL expiry, cache hit and miss paths, schema version invalidation. item Text cleaning utilities: stop pattern removal and MCQ-format detection. itemize Integration tests Integration tests in tests/test answer, sources, confidence, stage fig:sequence shows the interaction sequence exercised by these tests. figure[!ht] centering images/sequence_diagram_final.png System interaction sequence from API request receipt through retrieval, generation, confidence scoring, and response serialisation. fig:sequence figure Safety adversarial tests tests/test _safety _adversarial.py covers 24 adversarial inputs targeting three failure modes: emergency redirect bypass attempts, MCQ-format leakage from the MedMCQA training data, and sign-off pattern injection. End-to-end evaluation The end-to-end benchmark ( evaluation/run _e2e _benchmark.py) runs 36 questions through the offline pipeline and checks whether the retrieved context contains at least one keyword from the reference answer. The retrieval hit proxy is 0.972 --- 35 of 36 questions retrieve at least one relevant document. The single failure is a PubMedQA question about a rare surgical technique whose reference answer uses specialised terminology not well-represented in the knowledge base.

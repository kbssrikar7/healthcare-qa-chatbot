\chapter{\MakeUppercase{Technical Specification}}

\section{Requirements}

\subsection{Functional requirements}

\begin{enumerate}
    \item The system shall accept a free-text medical question in English and return a text answer.
    \item The system shall retrieve relevant documents from the knowledge base before generating an answer.
    \item The system shall return source attribution identifying \allowbreak{}which documents contributed to the answer.
    \item The system shall compute and return a confidence score for each response.
    \item The system shall run a hallucination check comparing \allowbreak{}the generated answer against retrieved sources.
    \item The system shall apply a safety guardrail that detects and flags questions involving emergency symptoms, prescription dosages, or self-harm.
    \item The system shall expose a \ac{rest} \ac{api} with endpoints for synchronous requests (\texttt{/ask}), streaming responses (\texttt{/ask/stream}), and a health check (\texttt{/health}).
    \item The system shall support cache lookup so that identical or near-identical questions within a session return quickly without re-running the full pipeline.
    \item The frontend shall display the answer, confidence breakdown, source list, and per-stage latency metrics.
\end{enumerate}

\subsection{Non-functional requirements}

\begin{enumerate}
    \item The system shall run without a \ac{gpu} and without internet access at inference time.
    \item The system shall not persist or log user query text.
    \item The system shall start up within 5 minutes on the target hardware.
    \item Warm-path \ac{api} latency shall be below 200 seconds for TinyLlama on \ac{cpu}.
    \item The system shall pass a suite of 250 automated tests covering unit, integration, and safety-adversarial cases.
    \item The Docker image shall reproduce local runtime behaviour for all \ac{api} endpoints.
    \item \ac{api} access shall require a key, with separate scopes for read and admin operations.
\end{enumerate}

\subsection{Safety and guardrail requirements}

\begin{enumerate}
    \item Questions matching emergency patterns --- chest pain, difficulty breathing, suicidal ideation, stroke symptoms --- shall receive a redirect to emergency services, not a generated answer.
    \item Questions requesting specific prescription dosages shall receive a redirect to consult a physician.
    \item All responses shall include a disclaimer that the system is not a substitute for professional medical advice.
    \item The system shall use an aggressive stop-word list to prevent the generation model from producing exam-format MCQ patterns (e.g., ``A) \ldots B) \ldots C) \ldots'') when the underlying dataset contains such formats.
\end{enumerate}

\section{Feasibility study}

\subsection{Technical feasibility}

The 1.1B-parameter TinyLlama model in bfloat16 occupies roughly 2.2 GB of \ac{ram}. My test machine had 16 GB available; retrieval (the BM25 index plus ChromaDB vector store) adds another 2--4 GB depending on knowledge base size, leaving adequate headroom. While a warm-path latency of 106 seconds is definitely too slow for real-time consumer interaction, it works well enough for a research prototype or an asynchronous queue where users submit a question and read the response a few minutes later. The BioMistral-7B model in 4-bit \ac{gguf} quantisation requires roughly 4 GB and runs at approximately 143 seconds mean latency.

\subsection{Data feasibility}

The three source datasets are all publicly available under open licences for research use. ChatDoctor-HealthCareMagic contains 226,000 real patient-doctor conversation pairs. PubMedQA provides 1,000 expert-annotated and 61,000 unlabelled question-answer pairs drawn from PubMed abstracts. MedMCQA contributes 187,000 multiple-choice questions from postgraduate medical entrance examinations. After filtering, deduplication, and sentence-boundary chunking, the combined knowledge base reaches 505,584 documents.

\subsection{Operational feasibility}

The system is packaged as a Docker container with a single entry point (\texttt{make run}). No external database infrastructure is required: ChromaDB runs as an embedded in-process store, and the BM25 index is persisted as a local pickle file. Startup takes 2--3 minutes on the test hardware, dominated by the time needed to load TinyLlama in bfloat16 on \ac{cpu}. Setting \texttt{SKIP\_STARTUP\_WARMUP=true} reduces cold-start time by deferring the model load to the first query, at the cost of a slower first response.
